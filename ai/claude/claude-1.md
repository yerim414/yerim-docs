# Claude 프롬프트 작성법 1

클로드 도입 후 가장 신경쓰였던 부분이다.

내가 생각하기엔 프롬프트작성에 따라 AI 사용차이가 확연이 난다고 생각한다.

그리고 프롬프트 작성에 대해 앤트로픽이 모범 가이드를 제공하는 만큼 프롬프트가 AI사용에 가장 큰 부분이라 생각한다.

참고로 새로운 모델이 나올때마다 해당 모델에 대한 프롬프트가 다르므로 신규 모델이 나올때마다 한번씩 읽어보기 위해 작성해본다.

***

프롬프팅의 모범사례는 앤트로픽에서도 제공하고 읽어보면 어렵지 않다.&#x20;

일단 그 누가봐도 좋은프롬프트와 나쁜프롬프트라고 느껴질만한 예시를 들어보면

```
로그인 기능 만들어줘.
```

```
현재 프로젝트에 로그인 기능을 추가해줘.

기존 인증 구조와 User 엔티티를 먼저 분석하고,
현재 Controller/Service 패턴을 우선 재사용해줘.

이메일/비밀번호 로그인과 Access Token 발급을 구현하고,
잘못된 인증 정보는 적절한 HTTP 상태 코드로 처리해줘.

새 라이브러리나 불필요한 추상화는 추가하지 말고,
구현 후 변경된 파일과 주요 변경 사항을 정리해줘.
```

어떤 사람이 보아도 두 프롬프트의 차이를 느낄 것이다.

첫 번째 프롬프트는 클로드가 아닌 내가 저런 작업 지시를 받아도 많은 부분을 추측하고 생각해야 한다.

어떤 프로젝트인지, 어떤 인증 방식인지, 로그인 기능을 만들려면 DB는 설계되어 있는지, 코드 스타일은 어떤지, 어디까지 구현해야 하는지...

클로드가 스스로 추측해야 하는 점이 많아진다.

개선된 프롬프트는 클로드가 추측해야 하는 부분이 크게 줄어든다. 정확히 어떤 프로젝트에서 어떤 기능을 해야 하는지, 해야 할 것과 하지 말아야 할 것 등이 적혀 있다.

간단히 말하자면 프롬프팅은 **신입사원에게 일을 시킨다고 생각하면 쉽다.**

내가 원하는 결과를 얻기 위해서는 단순히 "이거 해줘"라고 하는 것이 아니라, 어떤 일을 해야 하는지, 왜 해야 하는지, 어떤 것을 지켜야 하는지 등을 알려줘야 한다.

클로드에게 프롬프트를 작성하는 것도 이와 크게 다르지 않다

***

그런데 중요한 점은 프롬프트를 작성하다 보면 내용이 점점 길어질 수도 있다.

**프롬프트가 길다고 해서 좋은 프롬프트는 아니다.**

예를들어서 현재 프로젝트의 기술 스택이나 코드 구조등 클로드가 직접 확인 할 수 있는 정보까지는 굳이 길게 적어줄 필요가 없다.

신입사원에게 일을 시킬 때도 마찬가지다.

"로그인 기능 만들어주세요."라고 말하면 신입사원은 프로젝트를 확인하면서 무엇을 어떻게 해야 하는지 계속 판단하고 추측해야 한다.

반대로 "기존 인증 구조를 먼저 확인하고, 현재 프로젝트의 패턴을 유지하면서 이메일/비밀번호 로그인과 Access Token 발급을 구현해주세요."라고 말하면 해야 할 일이 훨씬 명확해진다.

**중요한건클로드가 작업을 수행하는 과정에서 불필요하게 추측해야하는 부분을 줄여주는것이다.**

***

**클로드가 알아서 추측해야 하는 부분은 줄이고, 내가 중요하게 생각하는 기준과 조건은 명확하게 전달하는 것.**

이것이 좋은 프롬프트를 작성하는 가장 기본적인 방법이라고 생각한다.
