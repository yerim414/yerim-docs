# Claude md 작성

프로젝트 루트에 두는 `CLAUDE.md`. 세션이 시작될 때 **자동으로 읽힌다.**

매 세션마다 **통째로 컨텍스트에 로드된다.** 길수록 매번 토큰을 많이 사용한다. 그래서 200줄을 넘기지 않게 작성 필요.

### 1단계 — /init 으로 초안 만들기

신규 작업을 할 repo 에서 init 명령어로 md를 만든다.

```
/init
```

기존에 있던 프로젝트면 전체를 싹 훑어서 초안을 만들어준다.

* 빌드·테스트·실행 명령 (`pyproject.toml`, `package.json`, `Makefile` 등)
* 폴더 구조와 역할
* 이미 있는 다른 AI 도구 규칙 파일 (`.cursorrules`, `.github/copilot-instructions.md`)

파일이 이미 있으면 새로 덮지 않고 보완한다.

### 2단계 — 무엇을 채울까

`/init` 으로 생긴 claude.md에 직접 필요한 내용을 추가 한다.

정답은 없고. 쓰다보니 편했던 내용을 적는게 좋은거 같음

| 섹션       | 내용                 | 예                          |
| -------- | ------------------ | -------------------------- |
| 명령어      | 실행, 테스트, 린트        | `pytest -q` — 기본은 unit만 돈다 |
| 구조       | 폴더 역할 한 줄씩         | `vendor/` 벤더별 어댑터          |
| 코드 규칙    | 포맷, import, 주석     | 한 줄 120자, import는 한 줄에 하나  |
| **주의사항** | **코드로는 알 수 없는 함정** | 이 API는 동시 호출하면 실패한다        |

### 3단계 — 작성 요령

구체적으로 적으면 좋음.

```markdown
❌ 코드를 깔끔하게 작성할 것
❌ 성능을 신경 쓸 것

✅ 함수는 50줄을 넘지 않게 나눈다
✅ 쿼리는 N+1이 생기지 않게 join 또는 selectinload를 쓴다
```

**절차는 넣지 않는다.** 배포 절차와 같은 내용은 세션 토큰만 먹는다. 이런 건 슬래시 커맨드나 스킬로 만드는게 좋다.

**200줄 미만.** 넘어가면 `.claude/rules/` 로 옮긴다. 경로별 규칙이라 해당 파일을 건드릴 때만 로드된다. `@import`로 파일을 나누는 건 결국 전부 로드되므로 토큰이 줄지 않는다.

**사람만 볼 메모는 HTML 주석으로.** 컨텍스트에 안 들어가서 토큰을 안 먹는다.

```markdown
<!-- 이 규칙은 2026-03 장애 이후 추가됨 -->
```

### 파일 위치 정리

여러 곳에 둘 수 있고, 있으면 전부 합쳐서 로드된다.

| 위치                    | 용도                |
| --------------------- | ----------------- |
| `~/.claude/CLAUDE.md` | 내 개인 취향 (모든 프로젝트) |
| `./CLAUDE.md`         | 팀이 공유하는 프로젝트 규칙   |
| `./CLAUDE.local.md`   | 이 프로젝트에서 나만 쓰는 설정 |

개인 취향(응답 톤, 언어 같은 것)을 프로젝트 파일에 넣으면 팀원까지 영향을 받는다. 전역에 두고 git 추적에 안잡히게 한다.

### 확인 명령

| 명령              | 용도                |
| --------------- | ----------------- |
| `/memory`       | 로드된 메모리 파일 목록과 편집 |
| `/context`      | 지금 컨텍스트를 얼마나 쓰는지  |
| `claude doctor` | 설정 진단, 정리할 항목 제안  |

명령어를 사용하거나 클로드한테 지금 md 한번 읽어줘 하면 잘 적용 되었는지 확인 가능하다.
