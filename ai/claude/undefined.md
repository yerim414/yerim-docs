# 하네스

하네스는 Claude가 특정 작업을 안정적으로 수행하도록 감싸고 통제하는 실행 환경/구조를 의미한다.

Claude의 하네스를 적용하면 이러한 구조이다.

```
┌─────────────────────────────┐
│        Claude Harness       │
│                             │
│  ┌───────────────────────┐  │
│  │       Claude AI       │  │
│  └───────────────────────┘  │
│            ↕                │
│  ┌───────────────────────┐  │
│  │ Tools / Skills / MCP  │  │
│  └───────────────────────┘  │
│            ↕                │
│  ┌───────────────────────┐  │
│  │   Project / Git / FS  │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
```

Claude 를 실제 작업에 투입하기 위해 주변에 붙여놓은 실행/제어 체계라고 이해 하면 된다.

**하네스는 어떤 도구를 켜고 끄는 개념이 아니다. 본인 상황에 맞게 직접 설계해 가는 과정이 하네스 이다.**

***

## 1. 하네스를 알아야 하는 이유

AI로 만들다 보면 아래 상황을 경험해 보았을 것이다.

* 같은 모델을 사용하지만 A프로젝트에서는 잘 되고, B프로젝트에서는 엉망이다.
* 프롬프트를 아무리 다듬어도 개선되지 않는 응답
* 스킬 호출이 실패했는데 조용히 넘어간다.

이런 원인은 대부분 모델이 아닌 모델 주변에 있다. 그 주변을 설계하는 일이 _**하네스 엔지니어링**_ 이다.

## 2. 하네스란?

하네스는 원래 말에 씌우는 마구를 뜻한다.

동사로 쓰면 강력한 것을 제어해서 유용하게 쓴다는 의미이다.

**AI에서도 모델은 강력하지만 그대로 두면 어디로 튈지 모른다. 하네스는 그 힘을 예측 가능한 방향으로 쓰게 만드는 구조이다.**

클로드를 작업하며 skill을 다운받고 Claude.md를 작성하고 나만의 신규 스킬을 만드는 것도 전부 하네스이다.

```
                 Claude Code
                     │
             ┌───────┴───────┐
             │    Harness    │
             └───────┬───────┘
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
  CLAUDE.md       Skills          MCP
  프로젝트 규칙   전문 작업        외부 도구
       │             │             │
       └─────────────┼─────────────┘
                     ↓
                실제 프로젝트
```

## 4. 하네스의 구성 및 시작 방법

거창하게 시작할 필요는 없다. 에이전트가 실수할 때마다,&#x20;

미첼 하시모토가 정의한방식이가장현실적이다.   &#x20;

**에이전트가 실수할때마다, 같은 실수를 다시 하지 않도록 장치를 하나씩 쌓아가는 것**

하네스는 아래와 같은 형식으로 성장한다.

```
처음
 │
 └─ Claude가 작업
       ↓
     실수 발생
       ↓
   원인 분석
       ↓
 ┌───────────────┐
 │ 장치 추가      │
 │               │
 │ Rule          │
 │ Skill         │
 │ Tool          │
 │ Test          │
 │ Workflow      │
 │ Guardrail     │
 └───────────────┘
       ↓
   다시 작업
       ↓
   또 다른 실수
       ↓
   장치 추가
       ↓
      반복
```

**실수 하나하나가 하네스의 규칙과 자동 검증으로 전환되는 것이다.**

***

아래는 내가 하네스에 대해 클로드에게 질문한 내용이다.

## 1. 스킬과 claude.md는 하네스의 일부인가요?

**맞습니다.** 다만 하네스 전체가 아니라 그중 한 층이에요.

CLAUDE.md는 "이 프로젝트에서 어떻게 행동해야 하는가"를 설명하는 온보딩 문서 역할이고, 스킬은 반복되는 노하우를 재사용 가능한 형태로 떼어놓은 것입니다. 여기에 MCP로 연결한 도구, 저장소 구조, 테스트 환경, 권한 설정까지 다 합쳐진 게 하네스예요. 지금까지 하신 작업(스킬 설치, CLAUDE.md 작성, 로컬 DB를 MCP로 붙이기)은 이미 하네스를 만들고 계셨던 겁니다. 이름만 몰랐을 뿐이죠.

## 2. 명령을 덜 하게 만드는 것이 하네스 인가요?

이건 **결과**에 가깝지, 정의는 아닙니다. 여기가 헷갈리기 쉬운 지점이에요.

핵심은 **피드백 루프**입니다. 프롬프트는 "이렇게 해줘"라고 _말하는_ 것이고, 하네스는 에이전트가 자기 결과물이 맞는지 _스스로 확인할 수 있게_ 만드는 겁니다. 테스트를 돌려보고, 린트가 걸리고, 빌드가 깨지고, 그래서 스스로 고치는 구조요. 사람이 매번 "여기 틀렸어"라고 말해줄 필요가 없어지니까 결과적으로 명령이 줄어드는 거죠.

미첼 하시모토는 이걸 아주 실용적으로 정의했습니다 — 에이전트가 실수할 때마다 같은 실수를 다시 하지 않도록 장치를 하나씩 쌓아가는 작업. 이 문장이 하네스 엔지니어링의 가장 정확한 감각입니다.

## 3. 규칙 문서만 잘 쓰면 되는거 아닌가요?

규칙 문서는 하네스의 한 층일 뿐입니다. 도구, 검증, 권한, 메모리가 다 하네스입니다. 문서만 두껍게 쓰는 건 흔한 실수예요.
