# 컨테이너 내부 좀비프로세스 관리

도커 컨테이너를 띄우고 내부를 접속해서 이런저런 작업을 하다보면 defunct process의 수가 늘어나 있는게 확인되었다.

kill을 하여도 삭제되지도 않는다. 이러한 프로세스의 ppid가 1번 이여서 1번을 kill 하면 컨테이너가 종료되는거라서 말이안된다..

## **❤️** **좀비 프로세스 발생 원인**

1. **부모 프로세스가 자식 프로세스 종료를 처리하지 않음**
    - `defunct` 프로세스는 이미 종료된 프로세스지만, 부모 프로세스가 `wait()` 또는 `waitpid()`를 호출하여 정리하지 않으면 남아 있다.
2. **PID 1이 올바르게 좀비 프로세스를 처리하지 않음**
    - 도커 컨테이너에서 실행되는 첫 번째 프로세스(PID 1)는 좀비 프로세스를 `reap(수거)`해야 한다.
    - 기본적으로 `bash`, `sh` 등의 쉘 스크립트는 PID 1로 실행되었을 때 좀비 프로세스를 정리하지 못할 수 있다.

## **❤️ 해결방안**

해결방안으로는 도커 실행시 시스템 init 관리자를 사용하게 하는것이다.
도커 실행 시 `--init` 옵션을 추가하면, `tini`라는 init 시스템을 사용하여 좀비 프로세스를 자동으로 정리할 수 있다.

```bash
# tini install
RUN dnf install -y tini
# tini를 엔트리포인트로 설정
ENTRYPOINT ["/usr/bin/tini", "--"]
```

도커 파일에 위의 내용만 추가하면 된다.

## **❤️ 정리**

도커 내부의 좀비 프로세스가 정리되지 않았던 이유는 PID 1이 올바르게 좀비 프로세스를 처리하지 않았기 때문입니다.

**init 시스템**은 시스템이 부팅될 때 처음 실행되는 **PID 1 프로세스**로, 모든 프로세스의 부모 역할을 하며 좀비 프로세스를 정리하는 역할을 합니다.

따라서 도커 내부의 좀비 프로세스를 정리하기 위해서는 init 시스템을 활용해야 합니다.
