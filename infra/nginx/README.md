# Nginx

{% embed url="https://nginx.org/" %}



Nginx 란?

고성능 오픈 소스 웹 서버이자 리버스 프록시, 로드 밸런서 소프트웨어다.



1. Nginx는 무엇인가?

Nginx는 웹 서버 소프트웨이어다.

쉽게 말하면 사용자의 요청을 받고, 필요한 데이터를 응답해 주는 프로그램 이다.

예를 들어서 Nginx가 설치된 서버에 띄우고자 하는 html이 있다면

```
사용자
   │
   │ GET /
   ▼
 Nginx
   │
   │ index.html 찾음 //<h1>Hello World</h1>
   ▼
사용자에게 파일 전달
```

위의 예시와 같이 Nginx를 실행하면 사용자가 브라우저로 서버에 접속했을때 Hello World가 출력되게 될것이다.

즉, **기본적인 역할은 웹페이지 파일을 사용자에게 보여주는 것이다.**



2. Node.js나 NestJs 서버

근데 프로젝트를 하다보면 그냥 Node.js에선 npm run을 통해서 내가지정한포트에서실행하게 된다.

```
사용자
   │
   │ /users 요청
   ▼
Node.js
   │
   ├── Controller
   ├── Service
   └── Database
```

근데 이미 Node서버에서도 요청을 받아 파일을 보여주고 있는데 Ngix가 필요한 이유는 뭘까..



3. Node.js와 Nginx의 역할은 다르다

Node.js는 애플리케이션을 실행하는 서버에 가깝다.

예를들어서 요청이 오면 실제로 그 요청을 반환하기 위한 일을 한다

```
/users 요청
     │
     ▼
Node.JS
     │
     ├── 사용자 조회
     ├── 비밀번호 검증
     ├── DB 조회
     └── 결과 반환
```

반면에 Nignx는 진짜 전달만 하는 역할을 한다.

```
요청 받기
  │
  ├── 파일 요청인가?
  │      └── 파일 전달
  │
  └── 다른 서버가 처리해야 하는 요청인가?
         └── 해당 서버로 전달
```

이처럼 같은 서버같지만 역할이 다르다.

AI에게 쉬운 설명을 요청했는데 다음과 같았다.

* **Nginx = 직원**
* **NestJS = 주방**

손님이 직원에게 주문을 하여도 직원이 직접 요리를 하지 않는다. 손님이 주문한 요리를 주방에게 전달하는 역할을 한다.

```
손님
  │ 주문
  ▼
Nginx
  │ 전달
  ▼
NestJS
  │ 실제 처리
  ▼
Nginx
  │ 결과 전달
  ▼
손님
```

이러한 구조를 **Reverse Proxy**라고 한다.

***

Nginx의 특징

1. 가볍고 많은 요청을 동시에 처리하는데 강하다

Nginx의 가장 대표적인 특징

일반적인 웹 서버는 요청마다 별도의 프로세를 생성하는 방식이 있을 수 있지만. Nginx는 이벤트기반, 비동기 방식으로 많은 연결을 효율적으로 처리한다.

```
요청 1 ─┐
요청 2 ─┤
요청 3 ─┼── Nginx가 효율적으로 처리
요청 4 ─┤
요청 5 ─┘
```

그래서 동시에 많은 사용자가 접속하는 환경에 적합하다.

2. 정적 파일 제공에 강하다

정적파일은 서버에서 별도의 계산 없이 그대로 전달 할 수 있는 파일이ㅏㄷ.

굳이 NestJS나 Node.js가 중간에서 처리할 필요 없이 Nginx가 바로 전달할 수 있다.

3. Reverse Proxy 기능

이게 현재 Nginx를 사용할 때 가장 많이 사용하는 기능 중 하나다.

```
사용자
   │
   ▼
Nginx
   │
   ▼
Node.js / NestJS / Python / Java
```

Nginx가 앞에서 요청을 받고 실제 애플리케이션 서버로 전달한다.



4. Load Balancing이 가능합니다

서버가 여러 대일 경우 요청을 분산할 수 있습니다.

```
                   ┌── Backend 1
사용자 → Nginx ────┼── Backend 2
                   └── Backend 3
```

예를 들어 사용자가 많이 접속하면

```
사용자 A → Backend 1
사용자 B → Backend 2
사용자 C → Backend 3
```

이런 식으로 부하를 나눌 수 있다.



5. HTTPS/SSL 처리를 담당할 수 있다

HTTPS 인증서를 Nginx에서 관리할 수 있습니다.

```
사용자
   │
   │ HTTPS
   ▼
 Nginx
   │
   │ HTTP 또는 HTTPS
   ▼
Backend Server
```

이렇게 하면 각각의 Backend 서버가 인증서를 직접 처리하지 않아도 된다.



**Nginx는 직접 복잡한 비즈니스 로직을 처리하기보다는, 많은 웹 요청을 효율적으로 받아서 처리하거나 적절한 서버로 전달하는 데 특화된 웹 서버입니다.**
