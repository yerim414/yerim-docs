# n8n

{% embed url="https://n8n.io/" %}

## n8n 이란?

워크플로 자동화 도구다.

"이 일이 생기면 이것들을 순서대로 실행해라"를 코드가 아니라 블록을 이어 붙여서 만든다.

### 1. 어떤 문제를 푸는 도구인가

이런 요청이 들어왔다고 하자.

> 매일 아침 9시에 어제 발생한 에러 로그를 정리해서 슬랙에 올려주세요.

보통은 파이썬 파일을 하나 만들어서 DB 조회하고, 문자열로 정리하고, 슬랙 API를 호출한 뒤
서버에 올려 crontab에 등록한다.

동작은 한다. 그런데 며칠 지나면 아쉬운 점이 생긴다.

* 알림이 안 왔는데 왜 안 왔는지 알 방법이 없다. 로그를 따로 남겼어야 한다.
* 슬랙 API가 잠깐 죽어서 실패했다면 재시도 코드를 직접 짰어야 한다.
* 비슷한 요청이 또 들어오면 파일 만들고 크론 걸고를 처음부터 반복한다.
* 기획자가 문구 하나 바꾸고 싶어도 코드를 볼 수 없으니 매번 개발자를 거쳐야 한다.

**n8n은 이 반복되는 부분을 대신 해준다.** 조회하고 가공하고 어딘가로 보내는 흐름만
화면에서 만들면 실행 기록, 재시도, 스케줄 관리는 n8n이 맡는다.

### 2. Zapier, Make와 다른 점

같은 부류의 서비스지만 n8n은 두 가지가 다르다.

* **내 서버에 직접 설치할 수 있다.** 그래서 외부에 열려 있지 않은 사내 DB에도 붙을 수 있다.
* **블록 안에 직접 코드를 쓸 수 있다.** 자바스크립트나 파이썬을 그대로 넣는다.

그래서 비개발자용 자동화 서비스보다 개발자에게 잘 맞는다.

## 워크플로와 노드

n8n을 켜면 빈 캔버스가 나온다. 여기에 **노드**를 놓고 **선**으로 잇는다.

```
[매일 아침 9시] → [DB에서 조회] → [보기 좋게 정리] → [슬랙에 보내기]
```

이 그림 한 장이 **워크플로(Workflow)** 다. 앞에서 말한 파이썬 파일 하나에 해당한다.

왼쪽에서 오른쪽으로 순서대로 실행되고, **선을 따라 데이터가 흘러간다.**
공장의 컨베이어 벨트를 떠올리면 된다.

### 1. 트리거 노드

워크플로의 맨 앞에 하나만 있는 시작 노드다. 언제 시작할지를 정한다.

| **노드** | **언제 시작하나** |
| --- | --- |
| Schedule Trigger | 정해진 시각에 시작한다. crontab을 대신한다. |
| Webhook | 지정된 주소로 HTTP 요청이 오면 시작한다. |
| Manual Trigger | 화면에서 버튼을 누르면 시작한다. 만드는 중 테스트용. |
| 앱 이벤트 | 새 메일 도착, 새 슬랙 메시지 등 외부 서비스의 사건. |

### 2. 일반 노드

시작된 뒤 실제 일을 하는 노드다. DB 조회, HTTP 요청, 슬랙 전송, 조건 분기, 코드 실행 등
종류가 수백 개다.

처음부터 다 알 필요는 없다. 필요할 때 검색창에 `Postgres`, `Slack` 처럼 쳐서 찾으면 된다.

## 데이터는 목록으로 흐른다

n8n에서 제일 헷갈리는 부분이자, 이것만 이해하면 나머지가 쉬워지는 개념이다.

노드와 노드 사이를 흐르는 데이터는 **항상 목록**이다. 값 하나가 아니라 여러 개가 줄지어 간다.
목록의 각 칸을 **아이템(Item)** 이라고 부른다.

DB에서 에러 로그 3건을 조회했다면 다음 노드로 이런 모양이 넘어간다.

```json
[
  { "level": "ERROR", "message": "DB timeout" },
  { "level": "ERROR", "message": "null pointer" },
  { "level": "ERROR", "message": "connection refused" }
]
```

아이템이 3개인 목록이다.

### 1. 아이템 개수만큼 반복 실행된다

**다음 노드는 이 아이템 하나하나에 대해 반복 실행된다.** 이게 핵심이다.

```
아이템 3개
   │
   ├── 1번 아이템 → 슬랙 전송
   ├── 2번 아이템 → 슬랙 전송
   └── 3번 아이템 → 슬랙 전송
```

반복문을 직접 쓰지 않았는데 알아서 3번 돈다. 컨베이어 벨트에 물건 3개가 올라오면
다음 공정이 3번 작동하는 것과 같다.

이걸 모르면 주문 100건을 조회했는데 슬랙 메시지가 100개 도착하는 일이 생긴다.

### 2. 하나로 합치려면 중간에서 묶는다

3건을 한 줄로 묶어서 한 번만 보내고 싶다면, 여러 아이템을 하나로 합쳐 주는 노드를
중간에 넣어야 한다.

정리하면 이렇다.

* 아이템이 N개면 뒤쪽 노드는 N번 실행된다.
* 한 번만 실행되게 하려면 중간에서 N개를 1개로 합쳐야 한다.

## 앞 노드의 데이터를 갖다 쓰기

슬랙 노드의 메시지 칸에 그냥 글자를 쓰면 항상 같은 문구만 나간다.
앞 노드가 조회한 실제 값을 넣으려면 **표현식(Expression)** 을 쓴다.

입력 칸의 `Fixed` / `Expression` 토글을 Expression으로 바꾸고 중괄호 두 개 안에 적는다.

```javascript
{{ $json.message }}
```

`$json`은 **지금 처리 중인 아이템**을 가리킨다.
위 예시에서 첫 번째 아이템 차례에는 `DB timeout`, 두 번째 차례에는 `null pointer`가 된다.

자바스크립트를 그대로 쓸 수 있다.

```javascript
{{ $json.name.toUpperCase() }}
{{ $json.price * 1.1 }}
{{ $now.minus(1, 'days').toISO() }}
```

바로 앞이 아니라 더 앞쪽 노드의 데이터가 필요하면 노드 이름으로 지정한다.

```javascript
{{ $node["에러 조회"].json.message }}
```

노드 이름이 참조에 쓰이므로 `HTTP Request1` 같은 기본값으로 두지 않는다.
나중에 이름을 바꾸면 이 참조가 깨진다.

## 자격증명은 따로 보관한다

DB 비밀번호나 API 토큰을 노드 안에 직접 적지 않는다.
n8n에는 **크리덴셜(Credential)** 이라는 별도 저장소가 있다.

```
크리덴셜 저장소 (암호화 보관)
   │
   ├── 워크플로 A 에서 사용
   ├── 워크플로 B 에서 사용
   └── 워크플로 C 에서 사용
```

한 번 등록해 두면 여러 워크플로에서 골라 쓰기만 하면 되고,
워크플로를 JSON으로 내보내도 자격증명은 따라 나가지 않는다.

## 실패했을 때

직접 짠 크론 스크립트 대비 가장 큰 이득이 이 부분이다.

**Executions** 탭에 모든 실행 기록이 남는다. 언제 돌았는지, 실패했다면 어느 노드에서
어떤 데이터를 받고 어떤 에러가 났는지까지 볼 수 있다. 실패한 건은 그 자리에서 다시 실행한다.

노드 설정(Settings)에서 재시도를 켤 수 있다.

| **항목** | **설명** |
| --- | --- |
| Retry On Fail | 실패 시 몇 번, 몇 초 간격으로 재시도할지 |
| On Error | 실패 시 워크플로를 멈출지, 무시하고 계속할지 |

워크플로 전체 설정에는 **Error Workflow** 항목이 있다.
"이 워크플로가 실패하면 저 워크플로를 실행해라"는 설정이다.
실패를 알리는 워크플로를 하나 만들어 두고 모든 워크플로에 걸어 두는 식으로 쓴다.

## 언제 쓰고, 언제 그냥 코드를 짜나

n8n이 나은 경우

* 여러 외부 서비스를 이어 붙이는 일 (DB에서 슬랙, 구글시트에서 노션 등)
* 실행 기록과 재시도가 필요한 정기 작업
* 개발자가 아닌 사람도 흐름을 보거나 문구를 고쳐야 하는 경우
* 일단 빠르게 만들어 보고 싶은 경우

그냥 코드를 짜는 편이 나은 경우

* 조건 분기와 반복이 복잡한 로직. 노드 그림이 스파게티가 된다.
* 테스트 코드를 제대로 쓰고 싶은 로직
* 처리량이 아주 많은 경우

실무에서는 섞어 쓴다. 복잡한 계산은 FastAPI로 API를 만들어 두고,
n8n은 정해진 시각에 그 API를 호출하고 결과를 알리고 실패하면 재시도하는 역할만 맡는다.

```
n8n                          애플리케이션
 │                                │
 ├── 정해진 시각에 시작           │
 ├── API 호출 ───────────────────▶│ 복잡한 계산
 │◀─────────────────────────── 결과│
 ├── 결과를 슬랙에 전달           │
 └── 실패하면 재시도              │
```

---

**n8n은 직접 복잡한 비즈니스 로직을 처리하기보다는, 여러 서비스를 순서대로 이어 붙이고
그 실행을 기록하고 관리하는 데 특화된 자동화 도구다.**
