# 멀티프로세스 vs 멀티스레드 장단점

[👩‍💻 멀티 프로세스 vs 멀티 스레드 비교 💯 완전 총정리](https://inpa.tistory.com/entry/%F0%9F%91%A9%E2%80%8D%F0%9F%92%BB-multi-process-multi-thread)

### 멀티스레드

하나의 프로세스 안에서 여러 개의 스레드를 만들어 동시에 작업하는 방식

메모리를 공유, 스택만 스레드 마다 존재

웹 서버가 대표적인 멀티스레드 응용 프로그램이다. 사용자가 서버 데이터베이스에 자료를 요청하는 동안 브라우저의 다른 기능을 이용할 수 있는 이유가 멀티 스레드 기능 때문이다. 하나의 스레드가 지연되더라도 다른 스레드는 작업을 지속할 수 있게 된다.

### 멀티프로세스

여러개의 독립된 프로세스가 동시에 동작 CPU 코어마다 병렬로 일하게 하는 방식

프로세스끼리 메모리 공간을 공유하지않는다.

---

### 멀티스레드의 장점

1. 메모리를 공유하므로 추가 자원 사용이 적다. 효율적
2. 같은 주소 공간을 쓰므로 스레드 간 데이터 교환이 빠르다.
3. 스레드는 프로세스보다 가볍다.
4. I/O 바운드 작업에 유리 하다

단점

1. 동기화 문제, 경쟁 상태, 데드락 같은 문제가 생길 수 있다.
2. 파이썬에서는 동시에 하나의 스레드만 cpu 작업을 할 수 있기 때문에 cpu바운드 작업은 효과가 없다

---

### 멀티프로세싱의 장점

1. 여러 cpu 코어를 동시에 활용할 수 있어 병렬 처리가 가능하다
2. 프로세스는 메모리를 따로 쓰기 때문에 한 프로세스가 죽어도 다른 프로세스에는 영향이 적다
3. gil 영향 없음

단점

1. 독립된 메모리를 사용하기때문에 메모리 사용량이 크다
2. 데이터 공유가 어렵다
3. 스레드 보다는 무겁다.

- 네트워크, 파일 입출력처럼 **대기 많은 I/O 작업** → **멀티스레딩**
- 수학 계산, 영상 처리 같은 **무거운 연산 작업** → **멀티프로세싱**
