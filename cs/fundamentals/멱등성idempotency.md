# 멱등성(Idempotency)

[🌐 HTTP의 멱등성 · 안정성 · 캐시성 💯 완벽 이해하기](https://inpa.tistory.com/entry/WEB-%F0%9F%8C%90-HTTP%EC%9D%98-%EB%A9%B1%EB%93%B1%EC%84%B1-%C2%B7-%EC%95%88%EC%A0%95%EC%84%B1-%C2%B7-%EC%BA%90%EC%8B%9C%EC%84%B1-%F0%9F%92%AF-%EC%99%84%EB%B2%BD-%EC%9D%B4%ED%95%B4%ED%95%98%EA%B8%B0)

멱등 이라는 단어의 뜻은 수학이나 전산학에서 연산을 여러 번 적용하더라도 결과가 달라지지 않는 성질을 의미한다.

같은 요청을 한번이나 여러번 보내어도 결과가 변하지 않는 성질을 말한다.

HTTP에 멱등성을 대입하면..

멱등성이 있음

```python
GET /users/1 -> 몇 번 호출해도 항상 같은 결과를 받는다.

PUT /users/1 {"name" : "강아지"} -> 여러 번 보내도 결과는 동일하다. (이름이 강아지이면 변화 X)

DELETE /users/1 -> 이미 삭제 된 후 호출해도 결과는 삭제되어 있다.
```

멱등성이 없음

```python
POST /orders → 호출할 때마다 새 주문이 생성됨 (결과가 계속 변함)

PATCH /balance/add → 호출할 때마다 잔액이 계속 늘어남
```

그런데 GET 요청으로 조회 후 → PUT 요청으로 리소스 변경 → 다시 GET 요청

이면 멱등성 위배? 라고 생각이 드는데

멱등성은 같은 요청을 반복했을 때 서버에 추가적인 변화를 일으키지 않는다 는 의ㅣ미이다.

데이터 내용이 변경될 수 있지만, 다른 요청이 변경한 것이기 때문에 멱등성의 위배가 아니다.

GET 메소드는 결국 멱등성에 문제가 없다.

정리하면 아래와 같다

| 메서드 | 멱등성 |
| --- | --- |
| GET | ✅ 있음 |
| PUT | ✅ 있음 |
| DELETE | ✅ 있음 |
| PATCH | ⚠ 경우에 따라 다름 |
| POST | ❌ 없음 |
