# TCP와 UDP

TCP와 UDP의 차이

TCP와 UDP 뭔지는 알고 있지만 막상 누군가 나에게 TCP와 UDP의 차이를 말하라 하면, 순간 머리가 하얘질거같다.. 그래서 다시 적어본다

***

일단 내가 알고있는 바로는 TCP는 신뢰성 있는 통신이고, UDP는 받는쪽이 받든 말든 그냥 보낸다로 알고 있다.

그리고 TCP는 느리고 UDP는 빠르다고 알고 있다.

방향 자체는 맞겠지만 더 자세히 덧붙이자면

> TCP는 데이터를 전송하기 전에 연결을 설정하고, 데이터가 정상적으로 전달되었는지 확인하며, 누락된 데이터가 있으면 재전송하는 신뢰성 있는 전송 프로토콜이다.
>
> UDP는 별도의 연결 설정이나 전달 확인 없이 데이터를 전송하기 때문에 빠르고 단순하지만, 데이터가 유실되거나 순서가 바뀌어도 UDP 자체에서 보장하지 않는다.

TCP는 **확인하면서 보내는 방식,** 즉 데이터 전송 후 그 전송에 대한 응답을 확인한&#xB2E4;**.**

```
연결 설정
   ↓
데이터 전송
   ↓
정상 수신 확인
   ↓
누락 시 재전송
   ↓
순서 보장
```

실제로 뜯어보면 더 복잡하겠지만. 핵심 순서는 위와 같다

UDP는 **일단 보낸다**. 상대방이 받았던 말던 일단 보내고 본다. 재전송 단계가 없다.

수신 확인이나 재전송 등의 신뢰성 보장 기능 없이 데이터를 전송한다.

***

TCP와 UDP의 연결 흐름을 보면 더 알기 쉽다.

```
[Client]                       [Server]

   ─── 연결 요청 ───────────────▶
   ◀── 연결 응답 ───────────────

   ─── 데이터 1 ───────────────▶
   ◀── 확인 ───────────────────

   ─── 데이터 2 ───────────────▶
   ◀── 확인 ───────────────────
```

**TCP는 데이터를 보내기 전에 연결을 맺는 과정이 있다.**

**3-way handshake**라고 한다.

```
Client                Server

SYN ─────────────────▶

       ◀──────── SYN + ACK

ACK ─────────────────▶

연결 완료
```

그리고 데이터를 전송하면서 신뢰성을 관리 한다.

UDP

```
[Client]                       [Server]

   ─── 데이터 1 ───────────────▶

   ─── 데이터 2 ───────────────▶

   ─── 데이터 3 ───────────────▶

   ─── 데이터 4 ───────────────▶
```

UDP는 서버와의 연결 과정이 없고, 수신 확인, 재전송, 순서보장 등이 없다.

그래서 구조가 단순하고 오버헤드가 적다.

***

| 구분      | TCP                           | UDP                     |
| ------- | ----------------------------- | ----------------------- |
| 정식 명칭   | Transmission Control Protocol | User Datagram Protocol  |
| 연결 방식   | **연결 지향형**                    | **비연결형**                |
| 연결 과정   | 통신 전 연결을 설정함                  | 별도 연결 과정 없음             |
| 신뢰성     | **보장함**                       | **보장하지 않음**             |
| 데이터 유실  | 유실 감지 후 재전송                   | 유실되어도 UDP가 재전송하지 않음     |
| 데이터 순서  | **순서 보장**                     | 순서 보장 안 함               |
| 수신 확인   | ACK 등을 통해 확인                  | 별도의 수신 확인 없음            |
| 속도      | 상대적으로 느릴 수 있음                 | 상대적으로 빠름                |
| 오버헤드    | 큼                             | 작음                      |
| 대표적인 사용 | SSH, HTTP/HTTPS, DB 통신        | DNS, Syslog, 실시간 스트리밍 등 |

한줄로 정리하면

**TCP는 정확하게 전달하는것이 중요할 때, UDP는 빠르게 전달하는 것이 중요할 때** 이다.
