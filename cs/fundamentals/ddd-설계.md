# DDD 설계

## DDD 설계란?

DDD(Domain-Driven Design)는 소프트웨어 시스템을 개발할 때 **도메인 모델을 중심**으로 설계하는 방법론입니다. 

DDD는 소프트웨어를 구축하는 과정에서 비즈니스 도메인을 이해하고 반영함으로써 소프트웨어의 복잡성을 줄이고 유지 보수성을 향상시키는 것을 목표로 합니다.

---

### DDD의 구성요소

1. **도메인 모델 (Domain Model)**: 소프트웨어 시스템의 핵심적인 부분으로, 비즈니스 도메인에 대한 이해를 바탕으로 설계됩니다. 도메인 모델은 엔티티, 값 객체, 도메인 서비스 등의 요소로 구성됩니다.
2. **엔티티 (Entity)**: 도메인에서 식별 가능한 개별 객체를 나타냅니다. 엔티티는 고유 식별자를 갖고 있으며 상태와 동작을 가질 수 있습니다.
3. **값 객체 (Value Object)**: 엔티티와는 달리 고유한 식별자를 갖지 않고, 속성 값에 의해 식별됩니다. 값 객체는 불변성을 가지며 동일한 속성 값으로 서로 구별됩니다.
4. **도메인 서비스 (Domain Service)**: 특정한 도메인 로직을 수행하는 서비스입니다. 도메인 서비스는 특정 엔티티나 값 객체에 속하지 않고, 도메인 전반에 걸쳐 다양한 기능을 제공할 수 있습니다.
5. **애그리게이트 (Aggregate)**: 관련된 엔티티와 값 객체를 묶어서 하나의 단위로 다룹니다. 애그리게이트는 일관성 경계를 정의하고 관련된 객체 간의 일관성을 보장합니다.
6. **도메인 이벤트 (Domain Event)**: 도메인에서 발생하는 중요한 사건을 나타내는 객체입니다. 도메인 이벤트는 시스템의 상태 변화를 기록하고, 도메인 모델 간의 통신에 사용됩니다.

---

### DDD 예시

DDD를 사용하여 블로그 시스템을 만들어 보겠습니다.

1. **도메인 이해**
    
    블로그 시스템에서 중요한 도메인은 사용자, 게시물, 댓글등이 핵심 도메인이 된다.
    

1. **핵심 개념 식별**
    
    엔티티, 값 객체, 도메인 서비스 등을 정의
    
    1. 엔티티 : 
    - 사용자 (User): 사용자의 정보를 관리하는 엔티티
    - 게시물 (Post): 블로그에 작성된 게시물을 나타내는 엔티티
    - 댓글 (Comment): 게시물에 작성된 댓글을 나타내는 엔티티
    
    b. 값 객체 :
    
    - 제목 (Title): 게시물이나 댓글의 제목을 나타내는 값 객체
    - 내용 (Content): 게시물이나 댓글의 내용을 나타내는 값 객체
    
    c. 도메인 서비스 :
    
    - 게시물 서비스 (PostService): 게시물 생성, 수정, 삭제 등의 비즈니스 로직을 처리하는 서비스
    
2. 애그리게이트 정의
    - **사용자 애그리게이트 (User Aggregate)**:
        - 사용자 (User)
        - 프로필 (Profile): 사용자의 추가 정보를 담은 값 객체
    - **게시물 애그리게이트 (Post Aggregate)**:
        - 게시물 (Post)
        - 댓글 (Comment)
    
3. **도메인 서비스 정의**
    - **게시물 서비스 (PostService)**:
        - 게시물 생성 (createPost): 새로운 게시물을 생성하는 메서드
        - 게시물 수정 (updatePost): 기존 게시물을 수정하는 메서드
        - 게시물 삭제 (deletePost): 게시물을 삭제하는 메서드
    
4. **도메인 이벤트 정의 (선택 사항)**
    
    도메인에서 발생하는 중요한 사건을 나타내는 객체입니다. 이를 활용하여 시스템의 상태 변화를 기록할 수 있습니다.
    
    - 게시물 생성 이벤트 (PostCreatedEvent): 게시물이 생성될 때 발생하는 이벤트
    - 댓글 생성 이벤트 (CommentCreatedEvent): 댓글이 생성될 때 발생하는 이벤트
