# TDD(Test-Driven Development, 테스트 주도 개발)

TDD(Test-Driven Development)는 소프트웨어 개발 방법론 중의 하나로, 테스트 주도 개발이라고도 불립니다.

TDD의 주요 아이디어는 코드를 작성하기 전에 테스트 케이스를 먼저 작성하고, 그 다음에 테스트를 통과시키기 위한 코드를 작성하는 것입니다. 이는 개발자가 소프트웨어가 예상대로 동작하는지를 확인하고, 코드 변경에 따른 부작용을 방지하기 위한 안전망 역할을 합니다.

**선 테스트, 후 구현**

## TDD의 주요 단계

1. **테스트 작성 단계 (Red)**:
    - 개발자는 코드의 기능을 정의하는 단위 테스트를 먼저 작성합니다. 이때 작성되는 테스트는 아직 구현되지 않은 기능을 나타내며, 테스트가 실패할 것으로 예상됩니다.
2. **코드 작성 단계 (Green)**:
    - 테스트를 통과시키기 위한 최소한의 코드를 작성합니다. 이 코드는 기능을 충족시키기 위한 가장 간단한 형태의 코드일 수 있습니다.
3. **리팩터링 단계 (Refactor)**:
    - 작성한 코드를 리팩터링하여 중복을 제거하고 가독성을 향상시킵니다. 이 과정에서 테스트를 통과하는 코드의 구조나 설계를 개선할 수 있습니다.

---

## TDD 장단점

**장점**

1. **신뢰성 향상**: TDD를 통해 작성된 테스트 케이스는 소프트웨어의 예상치 못한 동작이나 버그를 미리 발견하도록 도와줍니다. 이는 소프트웨어의 신뢰성을 향상시킵니다.
2. **설계 개선**: TDD는 코드를 작은 단위로 분리하고 각 단위를 독립적으로 테스트하도록 유도하여 더 모듈화되고 유연한 소프트웨어를 설계할 수 있게 합니다. 이는 코드의 재사용성을 높이고 유지보수를 용이하게 만듭니다.
3. **문서화**: 테스트 케이스는 소프트웨어의 동작을 문서화하는 역할을 합니다. 즉, 테스트 코드는 소프트웨어의 기능을 설명하고 문서화하는 역할을 하며, 새로운 개발자가 코드를 이해하는 데 도움이 됩니다.
4. **자동화된 테스트**: TDD를 사용하면 테스트를 자동화할 수 있습니다. 이는 개발자가 코드 변경에 따른 부작용을 신속하게 파악할 수 있게 도와줍니다.

**단점**

1. **시간과 비용**: 초기에 테스트 케이스를 작성하는 데 시간과 노력이 필요합니다. 특히 복잡한 기능을 개발할 때는 테스트 케이스 작성에 많은 시간이 소요될 수 있습니다.
2. **기술적인 난이도**: TDD를 적용하려면 테스트 코드를 작성하고, 이를 통과하는 코드를 작성하는 기술적인 능력이 필요합니다. 특히 초보적인 개발자에게는 학습 곡선이 있을 수 있습니다.
3. **유연성 제한**: 일부 개발자는 TDD가 개발 프로세스의 유연성을 제한한다고 느낄 수 있습니다. 특히 기능을 먼저 설계하고 구현하는 전통적인 개발 방식과 비교했을 때, TDD는 테스트 케이스에 의존하여 개발을 진행하기 때문입니다.
4. **완전한 테스트 커버리지 보장의 어려움**: 모든 상황을 고려하여 완전한 테스트 커버리지를 보장하는 것은 어려울 수 있습니다. 특히 복잡한 비즈니스 로직이나 특수한 상황을 다루는 경우에는 모든 케이스를 고려하기 어려울 수 있습니다.

TDD 도입시 초기 투자 비용과 기술적인 난이도를 고려해야 합니다.

## TDD 예시

파이썬으로 간단한 계산기 기능을 TDD를 이용하여 만들어보겠습니다.

1. **테스트 케이스 작성**

```python
import unittest
from calculator import add

class TestCalculator(unittest.TestCase):
    def test_addition(self):
        result = add(3, 5)
        self.assertEqual(result, 8)

if __name__ == '__main__':
    unittest.main()
```

계산기 모듈의 **`add`** 함수를 호출하고, 그 결과가 예상한 값인 8과 같은지 확인하는 단위 테스트입니다. 
현재로썬 테스트 케이스만 작성 되어 있기 때문에 실행한다면 오류가 날 것 입니다.

**`calculator`** 모듈을 작성합니다.

1. **코드작성**

ccalculator.py

```python
def add(x, y):
    return x + y
```

모듈 작성후 테스트 케이스를 실행시키면 테스트가 통과 될 것입니다.

1. **리팩터링 단계**

이제 코드가 동작하는 것을 확인했으므로 리팩터링을 수행할 수 있습니다. 현재의 **`add`** 함수는 이미 간단하고 명확하므로 추가적인 리팩터링은 필요하지 않을 수 있습니다.
