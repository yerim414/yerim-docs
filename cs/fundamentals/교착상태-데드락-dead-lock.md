# 교착상태, 데드락 (Dead Lock)

데드락은 **둘 이상의 작업이 서로가 가진 자원을 기다리느라 영원히 진행하지 못하는 상태.**

데드락의 조건

- 상호 배제(Mutual Exclusion) : 자원은 동시에 하나의 작업만 사용 가능
- 점유 대기(Hold and Wait) : 어떤 자원을 점유한 채로 다른 자원을 기다림
- 비선점(No Preemption) : 이미 점유한 자원을 강제로 뺏을 수 없음
- 환형 대기(Circular Wait) : 자원 대기 관계가 원형 고리를 이룬다.(A→B→C→A)

상황 예시

멀티 스레드에서 락을 여러 개 사용할 때(락의 순서가 불일치 할때)

데이터베이스 트랜잭션에서 테이블/행 락 순서가 엇갈릴때(가장 많이 겪음 ㅜㅜ)

OS자원(파일 락, 소켓 등)을 서로 다른 순서로 잡을 때

이벤트 루프(비동기)에서 서로 wait 하거나 wait중에 블로킹 I/O를 써서 진행이 막힐 때

데드락 방지 기법

예방 : 위 4가지 필요조건 중 하나라도 성립하지 않게 설계하는 방식

순서 정하기, 한번에 자원 모두 요청하기, 타임아웃 후 자원 강제 회수하기

회피 : 발생할 가능성을 피해서 자원 할당

은행원 알고리즘(Banker’s Algorithm)

각 프로세스의 최대 자원 요구량을 미리 알고 잇어야 한다.

안전 상태 인지 검사하고 자원 할당하기

탐지 후 회복 : 일단 데드락이 발생해도 괜찮다고 가정

주기적으로 Wait for Graph를 그려서 싸이클이 있는지 탐지한다.

발견되면 일부 프로세스를 중단하거나 자원을 뺏어 회복

무시 : 데드락이 발생할 확률이 낮다면 그냥 무시
