# MSA(Microservices Architecture)

MSA는 하나의 큰 시스템을 여러 개의 작은 서비스(마이크로서비스)로 나누어 설계하는 아키텍처 방식입니다.

기존 : 하나의 서버에 모든 기능이 다 있음(Monolithic)

MSA : 사용자 서비스 ,결재 서비스, 상품 서비스가 각각 독립된 서버/애플리케이션으로 동작

특징 및 개념

- 작은 단위의 서비스 : 하나의 서비스는 작고 명확한 책임을 가진다.
- 독립적인 배포 : 서비스별로 개별 배포 및 확장이 가능
- API 통신 : 마이크로서비스끼리는 api등으로 통신
- 데이터 분리 : 서비스마다 DB를 따로 사용

Monolithic vs MSA

| 항목 | Monolithic | MSA |
| --- | --- | --- |
| 구조 | 하나의 큰 서비스 | 여러 개의 독립된 서비스 |
| 배포 | 한 번에 전체 배포 | 개별 서비스만 배포 가능 |
| 확장성 | 전체 확장 | 필요한 서비스만 확장 |
| 장애 영향 | 하나 죽으면 전체 영향 | 개별 장애로 격리 가능 |
| 테스트 | 통합 테스트 중심 | 개별 유닛 테스트 많음 |
| 복잡도 | 낮음 (개발 초기 편함) | 높음 (운영/관리가 복잡) |

장점

- 서비스별 독립 개발, 테스트, 배포가능 → 개발 효율 향상
- 특정 서비스만 확장 가능 → 자원 절약
- 장애 격리 → 시스템 안정성 증가
- 기술 스택 독립 가능

단점

- 구현 복잡도 증가 (통신, 인증, 배포 등 고려할 것이 많다.)
- DB 분리로 인한 트랜잭션 처리 어려움

MSA의 설명을 보자마자 네이버 페이지가 떠올랐다. 뉴스, 쇼핑, 블로그 등 여러 시스템이 이루어져 네이버 웹 하나가 만들어지고 각 기능들은 독립적으로 실행중이다.
