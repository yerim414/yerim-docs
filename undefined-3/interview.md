<summary>HTTP와 HTTPS의 차이는 무엇인가요?</summary>

HTTP와 HTTPS의 차이는 보안입니다. HTTP는 암호화를 거치지 않고 평문으로 요청을 보내게 되어 보내는 내용이 유출 될 수 있습니다. 반면에 HTTPS는 SSL인증을 추가하여 요청시 암호화를 하기 때문에  더 안전하게 데이터를 요청, 전송 할 수 있습니다.

**모범 답변**

**HTTP와 HTTPS의 가장 큰 차이는 통신 보안입니다.**\
**HTTP는 클라이언트와 서버가 데이터를 평문으로 주고받기 때문에 통신 과정에서 데이터가 노출되거나 변조될 위험이 있습니다.**

**HTTPS는 HTTP통신에 TLS 기반의 보안 계층을 추가한 방식입니다. 이를 통해 통신 데이터를 암호화하고, 데이터의 위변조를 방지하며, 인증서를 통해 서버의 신원을 확인 할 수 있습니다.**

**따라서 로그인 정보나 개인정보처럼 민감한 데이터를 전달하는 서비스에서는 HTTPS를 사용하는 것이 중요합니다.**

현재 내가 하고 있는 보안서비스도 api요청 시 데이터가 노출되면 안되기 때문에 HTTPS를 사용중!

<summary>TCP와 UDP의 차이는 무엇인가요?</summary>

TCP와 UDP의 차이는 신뢰도 입니다. TCP는 요청을 받는 쪽에서 보낸 요청에 대한 상태를 리턴하게 됩니다. 만약 누락된 요청이 있으면 다시보내기도 합니다. 이처럼 받는쪽의 응답을 기다리기 때문에 속도가 느리고, 받은 데이터의 오류 여부를 확인하기 때문에 오버헤드가 큽니다.

\
UDP는 요청을 받는 쪽이 요청을 받았나 받지 않았나에 대한 응답이 없습니다. 이때문에 누락이 발생하여도 다시 보내는 동작은 하지 않습니다. 또한 UDP가 더 빠르고 구성도 더 간단합니다. Syslog 전송에 사용합니다.

**모범답안**

**TCP와 UDP의 가장 큰 차이는 연결 방식과 데이터 전달의 신뢰성입니다.**

**TCP는 연결 지향형 프로토콜로, 통신 전에 연결을 수립한 후 데이터를 전송합니다. 데이터가 정상적으로 전달되었는지 확인하고, 데이터가 유실되면 재전송하기 때문에 신뢰성 있는 통신을 제공합니다. 대신 이러한 과정 때문에 UDP보다 오버헤드가 크고 상대적으로 느릴 수 있습니다.**

**UDP는 비연결형 프로토콜로 별도의 연결 과정이나 전달 확인 과정이 없이 데이터를 전송합니다. 데이터 유실이 발생해도 기본적으로 재전송하지 않기 때문에 신뢰성은 TCP보다 낮지만 오버헤드가 적고 빠릅니다.**

**따라서 정확한 데이터 전달이 중요한 웹 통신이나 파일 전송에는 TCP를 사용하고, 일부 데이터 유실보다 실시간성이 중요한 스트리밍이나 실시간 통신 등에 UDP를 사용 할 수 있습니다.**

<summary>프로세스와 스레드의 차이는?</summary>

프로세스는 하나의실행단위이며스레드는 프로세스 안에서 동작하는 각 작업 입니다.

프로세스는 프로세스 끼리 서로 자원을 공유하지 않습니다. 하지만 프로세스 내부의 작업 스레드는 각 자원을 공유합니다.



**모범답안**

**프로세스와 스레드는 모두 프로그램의 실행단위 입니다.**

**프로세스는 실행중인 프로그램을 의미하며, 운영체제로부터 독립적인 메모리 공간과 자원을 할당받습니다.**

**스레드는 프로세스 내부에서 실행되는 작업단위입니다. 같은 프로세스 안에 속한 스레드는 코드나 데이터와 같은 일부 메모리 자원을 공유합니다.**

**따라서 프로세스는 서로 독립적이기 때문에 하나의 프로세스에 문제가 발생해도 다른 프로세스에 미치는 영향이 상대적으로 적습니다. 반면 스레드는 자원을 공유하기 때문에 생성비용이나 통신 비용은 적지만, 하나의 스레드에서 문제가 발생하면 같은 프로세스의 다른 스레드에도 영향을 줄 수 있습니다.**

<summary>DB Connection Pool은 무엇이고, 왜 필요한가요?</summary>

DB Connection Pool은 일단 연결하고자 하는 DB의 연결을 미리만들어 두어 DB 요청 작업을 해당 pool에서 사용 후 사용이 완료되면 반환하는 것을 말합니다.

해당 커넥션 풀이 필요한 이유는 DB의 연결 요청이 매우 무거운 작업이기 때문입니다.



**모범답안**

**DB Connection Pool은 애플리케이션에서 사용할 DB Connection을 미리 생성해 Pool에 보관하고, 요청이 발생하면 Connection을 새로 생성하는 대신 Pool에 있는 Connection을 가져와 사용하는 방식입니다.**

**DB Connection을 생성할 때는 네트워크 연결이나 인증 등의 비용이 발생하기 때문에 요청마다 Connection을 새로 생성하면 성능에 부담이 발생할 수 있습니다.**

**따라서 Connection Pool을 사용하면 기존 Connection을 재사용하여 성능을 개선하고, 동시에 DB에 생성되는 Connection 수를 제한하여 DB 자원을 효율적으로 관리할 수 있습니다.**

**작업이 완료되면 Connection을 종료하는 것이 아니라 Pool에 반환하여 다른 요청이 다시 사용할 수 있도록 합니다.**

</details>

Image는 Container로 올리기 전 단계이며, 올리고자 하는 프로젝트의 여러 설정이 압축되어 있습니다.

Container는 Image를 실행시킨 형태로 하나의 가상 환경을 올린거라 보시면 됩니다.



**모범답안**

**Docker Image는 Container를 실행하기 위한 템플릿 입니다. 애플리케이션 코드와 실행에 필요한 런타임, 라이브러리, 환경 설정 등을 포함하고 있습니다.**

**Docker Container는 이러한 Image를 기반으로 실제 실행된 인스턴스 입니다.**

**예를 들어 하나의 Image를 만들고 이를 기반으로 여러 개의 Container를 실행할 수 있습니다.**

**Docker를 사용하면 개발 환경과 운영 환경의 실행환경을 동일하게 구성할 수 있기 때문에 환경 차이로 발생하는 문제를 줄일 수 있고, 애플리케이션을 독립적인 단위로 배포하고 관리할 수 있습니다.**

</details>

<summary>Database Index란 무엇이며, 왜 사용하나요?</summary>

데이터 베이스의 인덱스는 데이터베이스에서 데이터 검색시 빨리 검색하기 위한 용도 입니다.

인덱스를 많이 설정하면 그 인덱스만큼 용량을 차지하기 때문에 적절하게 설계 해야합니다.



**모범답안**

**Database Index는 데이터베이스에서 특정 데이터를 빠르게 조회하기 위해 사용하는 자료구조 입니다.**

**Index가 없으면 많은 데이터를 순차적으로 확인해야 하지만, Index를 사용하면 별도의 자료구조를 통해 원하는 데이터를 더 효율적으로 찾을 수 있습니다.**

**다만 Index를 많이 생성하면 저장 공간을 사용하고, 데이터가 Insert, Update, Delete 될 때 Index도 함께 관리해야 하기 때문에 쓰기 성능에는 비용이 발생 할 수 있습니다.**

**따라서 자주 조회되는 컬럼을 기준으로 적절하게 Index를 설계하는 것이 중요합니다.**

트랜잭션이 정상적으로 완료되면 Commit을 통해 작업내용을 반



**모범답안**

<summary>GET과 POST의 차이는 무엇인가요?</summary>

GET과 POST는 일단 HTTP의 메소드 입니다.

GET은 데이터를 읽어오는것이며 POST는 새로운 데이터를 생성할때 사용합니다.



**모범답안**

**GET과 POST는 HTTP Method입니다.**

**GET은 주로 서버의 데이터를 조회할 때 사용하고, POST는 새로운 리소스를 생성하거나 서버에 특정 작업을 요청할 때 사용합니다.**

**일반적으로 GET 요청은 조회를 목적으로 하기 때문에 서버의 상태를 변경하지 않는 것이 원칙이며, 같은 요청을 여러 번 수행해도 결과가 동일한 멱등성을 가집니다.**

**반면 POST는 요청을 여러 번 수행했을 때 새로운 데이터가 반복 생성될 수 있기 때문에 일반적으로 멱등하지 않습니다.**

<summary>동기(Synchronous)와 비동기(Asynchronous)의 차이는 무엇인가요?</summary>

동기는 작업이 순차적으로 실행되는것이고 비동기는 여러 작업을 동시에 실행하는 것 입니다.

비동기가 필요한 이유는 여러 작업이 있을때 하나씩 처리하는것보다 병렬로 여러개 처리하면 속도가 더 빠르기 때문입니다.

비동기라고 무조건 동시에 실행되는건 아니고 그 뭐냐.. 어떤 함수를 이용하면 해당 동기가 끝난 뒤 다음 동기를 실행 할 수 있게 해주는데 기억이 안나네요...

실제 백엔드에서 제가 경험해본 바로는 장비 동기화 시 여러장비의 입력이 들어오게 되면 동시에 처리하도록 해두었습니다.



**모범답안**

**동기와 비동기의 차이는 작업의 완료를 기다리는 방식에 있습니다.**

**동기 방식은 이전 작업이 완료될때 까지 다음 작업을 진행하지않고 기다리는 방식 입니다.**

**반면 비동기는 작업을 요청한 후 완료될 때까지 기다리지 않고 다른 작업을 수행할 수 있으며, 작업이 완료되면 결과를 받아 후속 작업을 처리할 수 있습니다.**

**예를 들어 백엔드에서 외부 API 호출이나 파일 I/O 처럼 응답을 기다리는 시간이 긴 작업에서는 비동기를 사용하면 기다리는 동안 다른 요청을 처리할 수 있어 시스템 자원을 효율적으로 사용할 수 있습니다.**

</details>

<summary>Nginx는 무엇이며, 왜 사용하는가요?</summary>

Nginx는 웹서버입니다. Nginx를 사용하는 이유는 요청을 Nginx가 받아 각 요청을 처리할 수 있는곳으로 보내줄 수 있기 때문 입니다. 이것이 리버스 프록시 입니다...?



**모범답안**

**Nginx는 웹 서버와 리버스 프록시 등의 역할을 수행할 수 있는 서버입니다.**

**일반적으로 Client가 Backend Application에 직접 요청하지 않고 Nginx가 앞단에서 요청을 먼저 받은 뒤 적절한 Backend Server로 전달하는 Reverse Proxy 구조로 많이 사용합니다.**

**이를 통해 Backend Application을 외부에 직접 노출하지 않고, SSL/TLS 처리나 정적 파일 제공, Load Balancing등의 역할을 Nginx에서 처리할 수 있습니다.**

**따라서 여러 Backend Server를 운영하거나 Client와 Application Server 사이의 요청을 효율적으로 관리 하기 위해 사용할 수 있습니다.**

</details>

<summary>SQL JOIN이란 무엇이며, INNER JOIN과 LEFT JOIN의 차이는 무엇인가요?</summary>

JOIN은 두 테이블간 조건에 맞는 데이터를 모아보는 것 입니다.

이너 조인은 두 테이블에서 where절조건에맞는공통으로 들어있는 데이터만을 결과로 반환합니다.

Left Join은 두 테이블에서 왼쪽의 데이터는 where절의 조건과 상관없이 출력하는 것 입니다.



**모범답안**

**JOIN은 여러 테이블에 분리되어 있는 관계 있는 데이터를 결합해서 조회하기 위한 기능입니다.**

**이너 조인은 조인 조건에 일치하는 데이터가 양쪽 테이블에 모두 존재하는 경우에만 결과를 반환합니다.**

**레프트 조인은 왼쪽 테이블의 데이터는 모두 반환하고, 오른쪽 테이블의 데이터 중 일치하는 데이터가 없으면 해당 컬럼은 Null로 반환합니다.**

</details>

<summary>REST API란 무엇이며, RESTful하게 API를 설계한다는 것은 무엇인가요?</summary>

REST API란 REST 규칙에 맞게 작성한 API를 뜻합니다.

RESTful하게 API를 설계한다는 것은 REST 규칙을 준수하여 설계한다는것입니다.

REST 규칙은... 기억이 잘 안나네요..



**모범답안**

**Rest api는 http의 특성을 활용하여 리소스를 중심으로 설계하는 API 방식입니다.**

**URL은 리소를 표헌하고, 리소스에 대한 조회, 생성, 수정, 삭제 등의 동작 은 HTTP Method를 통해 구분합니다.**

**Restful하게 API를 설계한다는 것은 이러한 원칙에 따라 URL과 HTTP Method를 일관성 있게 사용하는것을 의미합니다.**
