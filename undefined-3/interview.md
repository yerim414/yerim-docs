<summary>HTTP와 HTTPS의 차이는 무엇인가요?</summary>

HTTP와 HTTPS의 차이는 보안입니다. HTTP는 암호화를 거치지 않고 평문으로 요청을 보내게 되어 보내는 내용이 유출 될 수 있습니다. 반면에 HTTPS는 SSL인증을 추가하여 요청시 암호화를 하기 때문에  더 안전하게 데이터를 요청, 전송 할 수 있습니다.

**모범 답변**

**HTTP와 HTTPS의 가장 큰 차이는 통신 보안입니다.**\
**HTTP는 클라이언트와 서버가 데이터를 평문으로 주고받기 때문에 통신 과정에서 데이터가 노출되거나 변조될 위험이 있습니다.**

**HTTPS는 HTTP통신에 TLS 기반의 보안 계층을 추가한 방식입니다. 이를 통해 통신 데이터를 암호화하고, 데이터의 위변조를 방지하며, 인증서를 통해 서버의 신원을 확인 할 수 있습니다.**

**따라서 로그인 정보나 개인정보처럼 민감한 데이터를 전달하는 서비스에서는 HTTPS를 사용하는 것이 중요합니다.**

현재 내가 하고 있는 보안서비스도 api요청 시 데이터가 노출되면 안되기 때문에 HTTPS를 사용중!

<summary>TCP와 UDP의 차이는 무엇인가요?</summary>

TCP와 UDP의 차이는 신뢰도 입니다. TCP는 요청을 받는 쪽에서 보낸 요청에 대한 상태를 리턴하게 됩니다. 만약 누락된 요청이 있으면 다시보내기도 합니다. 이처럼 받는쪽의 응답을 기다리기 때문에 속도가 느리고, 받은 데이터의 오류 여부를 확인하기 때문에 오버헤드가 큽니다.

\
UDP는 요청을 받는 쪽이 요청을 받았나 받지 않았나에 대한 응답이 없습니다. 이때문에 누락이 발생하여도 다시 보내는 동작은 하지 않습니다. 또한 UDP가 더 빠르고 구성도 더 간단합니다. Syslog 전송에 사용합니다.

**모범답안**

**TCP와 UDP의 가장 큰 차이는 연결 방식과 데이터 전달의 신뢰성입니다.**

**TCP는 연결 지향형 프로토콜로, 통신 전에 연결을 수립한 후 데이터를 전송합니다. 데이터가 정상적으로 전달되었는지 확인하고, 데이터가 유실되면 재전송하기 때문에 신뢰성 있는 통신을 제공합니다. 대신 이러한 과정 때문에 UDP보다 오버헤드가 크고 상대적으로 느릴 수 있습니다.**

**UDP는 비연결형 프로토콜로 별도의 연결 과정이나 전달 확인 과정이 없이 데이터를 전송합니다. 데이터 유실이 발생해도 기본적으로 재전송하지 않기 때문에 신뢰성은 TCP보다 낮지만 오버헤드가 적고 빠릅니다.**

**따라서 정확한 데이터 전달이 중요한 웹 통신이나 파일 전송에는 TCP를 사용하고, 일부 데이터 유실보다 실시간성이 중요한 스트리밍이나 실시간 통신 등에 UDP를 사용 할 수 있습니다.**

<summary>프로세스와 스레드의 차이는?</summary>

프로세스는 하나의실행단위이며스레드는 프로세스 안에서 동작하는 각 작업 입니다.

프로세스는 프로세스 끼리 서로 자원을 공유하지 않습니다. 하지만 프로세스 내부의 작업 스레드는 각 자원을 공유합니다.

<summary>DB Connection Pool은 무엇이고, 왜 필요한가요?</summary>

DB Connection Pool은 일단 연결하고자 하는 DB의 연결을 미리만들어 두어 DB 요청 작업을 해당 pool에서 사용 후 사용이 완료되면 반환하는 것을 말합니다.

해당 커넥션 풀이 필요한 이유는 DB의 연결 요청이 매우 무거운 작업이기 때문입니다.

</details>

<summary>Docker Image와 Container의 차이는 무엇인가요?</summary>

Image는 Container로 올리기 전 단계이며, 올리고자 하는 프로젝트의 여러 설정이 압축되어 있습니다.

Container는 Image를 실행시킨 형태로 하나의 가상 환경을 올린거라 보시면 됩니다.
